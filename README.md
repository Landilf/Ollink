# Ollink

Android-приложение для чата с моделями, запущенными через Ollama на ноутбуке или другом компьютере в локальной сети. Телефон отправляет историю диалога на компьютер и получает ответ по мере генерации. Вычисления выполняются на компьютере; модель на телефоне не запускается.

Интерфейс написан на **Kotlin и Jetpack Compose**, архитектура — **Clean Architecture + MVVM** с однонаправленным потоком состояния.

```text
Телефон с Ollink ←→ локальная сеть / HTTP ←→ Ollama на компьютере ←→ модель
```

## Возможности

- Выбор установленной модели из списка Ollama.
- Потоковый вывод ответа, остановка запроса и повторная генерация последнего ответа.
- Несколько диалогов с сохранением сообщений и черновиков между запусками.
- Поиск чатов по названиям и содержимому, переименование и удаление.
- Копирование ответов и выделение текста.
- Базовое форматирование ответов: заголовки, жирный текст, встроенный код и блоки кода.
- Подсказки для начала разговора в сетке 2×2.
- Светлая и тёмная темы по настройке Android.
- Адаптивная компоновка для телефонов, широких окон, горизонтальной ориентации и крупного шрифта.

## Подключение к Ollama

### 1. Подготовьте компьютер

Установите [Ollama](https://ollama.com/download) и проверьте установленные модели:

```bash
ollama list
```

Если моделей нет, загрузите нужную через `ollama pull ИМЯ_МОДЕЛИ`, заменив `ИМЯ_МОДЕЛИ` её названием. Для чата нужна модель, поддерживающая API `/api/chat`.

По умолчанию Ollama слушает `127.0.0.1:11434`, поэтому с телефона недоступна. Для доступа из локальной сети настройте `OLLAMA_HOST=0.0.0.0:11434`. [Документация Ollama](https://docs.ollama.com/faq#how-can-i-expose-ollama-on-my-network).

При **ручном запуске** на Linux или macOS:

```bash
OLLAMA_HOST=0.0.0.0:11434 ollama serve
```

Если Ollama уже запущена службой или приложением, настройте переменную для этого процесса и перезапустите его. Второй экземпляр не сможет занять тот же порт. Инструкции для Linux/systemd, macOS и Windows: [настройка сервера Ollama](https://docs.ollama.com/faq#how-do-i-configure-ollama-server).

#### NixOS

Добавьте параметры в существующую конфигурацию Ollama:

```nix
services.ollama = {
  enable = true;
  host = "0.0.0.0";
  openFirewall = true;
};
```

Примените конфигурацию обычным для вашей системы способом, например:

```bash
sudo nixos-rebuild switch
```

Описание сервиса: [Ollama в NixOS](https://wiki.nixos.org/wiki/Ollama).

### 2. Узнайте адрес и проверьте сеть

Телефон и компьютер должны быть в одной локальной сети. На Linux адрес можно посмотреть командой:

```bash
ip -4 addr
```

Найдите строку `inet` у интерфейса Wi-Fi (`wlp…`, `wlan…`) или Ethernet (`enp…`, `eth…`). Например, `192.168.1.42/24` означает, что адрес компьютера — `192.168.1.42`.

Разрешите входящие подключения к TCP-порту **11434** из своей локальной сети в firewall компьютера. Полностью отключать firewall для этого не требуется.

Откройте на телефоне в браузере:

```text
http://192.168.1.42:11434/api/tags
```

Замените адрес на IP своего компьютера. Должен появиться JSON со списком моделей. Гостевая Wi-Fi-сеть или изоляция клиентов на роутере могут запрещать связь между устройствами.

### 3. Подключите приложение

1. Откройте боковое меню → **«Подключение к Ollama»** или кнопку настройки в пустом чате.
2. Введите адрес сервера, например `http://192.168.1.42:11434`, без `/api/tags` и других путей.
3. Нажмите **«Подключиться»**.
4. Выберите модель в верхней панели и отправьте сообщение.

Адрес и выбранная модель сохраняются. При следующем запуске приложение автоматически проверяет сохранённый сервер.

`localhost` и `127.0.0.1` на телефоне обозначают сам телефон. В стандартном Android Emulator для обращения к компьютеру используется `http://10.0.2.2:11434`. [Сеть Android Emulator](https://developer.android.com/studio/run/emulator-networking).

## Использование

| Действие | Как выполнить |
|---|---|
| Создать диалог | Кнопка `+` сверху или «Новый чат» в боковом меню |
| Выбрать модель | Нажать на название модели в верхней панели |
| Найти диалог | Поле поиска в боковом меню; поиск учитывает названия и сообщения |
| Переименовать или удалить чат | Меню `…` рядом с чатом, долгое нажатие на название или меню текущего чата сверху |
| Остановить ответ | Нажать кнопку остановки, которая заменяет отправку во время запроса |
| Повторить последний ответ | Кнопка под последним ответом или «Повторить ответ» в меню текущего чата |
| Скопировать ответ | Кнопка копирования под ответом |
| Использовать подсказку | Нажать карточку: текст появится в поле ввода без автоматической отправки |

При остановке уже полученная часть ответа остаётся в чате. При ошибке реплика пользователя сохраняется, чтобы можно было повторить запрос. Повторная генерация заменяет последний ответ и сохраняет предшествующий контекст.

Черновик привязан к диалогу: переключение между чатами не теряет набранный текст. Во время генерации можно заранее набирать следующее сообщение; переключение чатов и моделей доступно после завершения или остановки запроса.

Смена модели в непустом диалоге создаёт новый чат и сохраняет предыдущий. Чаты также привязаны к адресу сервера: история не отправляется автоматически на другой компьютер. При смене адреса сервера для непустого чата создаётся отдельный диалог.

### Адаптивный интерфейс

На узком экране история открывается в выдвижном меню. При ширине от **840 dp**, либо от **600 dp**, когда доступное окно шире своей высоты, история находится рядом с перепиской.

Область сообщений и ввода ограничена **760 dp** и центрируется на широком экране. Сообщения пользователя занимают не более 85% ширины области переписки. Поле ввода растёт до шести строк; его предел учитывает доступную высоту и масштаб шрифта.

В небольших окнах используются компактные отступы и прокрутка. При недостатке высоты или крупном шрифте боковая панель прокручивается целиком. Сетка подсказок сохраняет расположение 2×2.

Системные панели и вырезы учитываются через window insets. Клавиатура сдвигает содержимое через `imePadding`; выбор расположения истории не меняется на каждом кадре её анимации, а ограничение высоты ввода учитывает конечную высоту клавиатуры.

## Сборка

Откройте корень проекта в Android Studio и выполните Gradle Sync. Для сборки нужны Android SDK Platform **36.1** и JDK **21**. Требования к JVM Gradle daemon заданы в [gradle/gradle-daemon-jvm.properties](gradle/gradle-daemon-jvm.properties).

| Параметр | Значение |
|---|---|
| Модуль | `app` |
| Application ID / namespace | `ru.landilf.ollink` |
| Язык | Kotlin |
| UI | Jetpack Compose / Material 3 |
| Android Gradle Plugin | 9.2.1 |
| Gradle Wrapper | 9.4.1 |
| Compose Compiler plugin | 2.2.10 |
| Compose UI | 1.11.4 |
| Material 3 | 1.4.0 |
| Compile SDK | 36.1 |
| Target SDK | 36 |
| Min SDK | 26 — Android 8.0 |
| Java source / target compatibility | 11 |

Версии зависимостей находятся в [gradle/libs.versions.toml](gradle/libs.versions.toml). Kotlin подключён встроенными средствами AGP; для Compose используется отдельный compiler plugin.

Путь к Android SDK задаётся локально через Android Studio или `local.properties` (`sdk.dir`). Машинные пути не нужно переносить в репозиторий.

Сборка debug APK:

```bash
./gradlew :app:assembleDebug
```

В Windows используйте `gradlew.bat`. Готовый APK:

```text
app/build/outputs/apk/debug/app-debug.apk
```

Его можно установить на телефон вручную или запустить приложение из Android Studio.

## Архитектура

Один Gradle-модуль с разделением слоёв по пакетам. Подход соответствует DACtune: **Clean Architecture + MVVM + UDF**, внедрение зависимостей через конструкторы и `AppContainer`.

```text
app/src/main/java/ru/landilf/ollink/
├── OllinkApplication.kt
├── di/                 # AppContainer и фабрика ViewModel
├── presentation/       # Activity, Compose, ViewModel, UiState, Action, Event
│   ├── components/     # Переписка, история, диалоги, форматирование текста
│   └── theme/          # Светлая и тёмная темы Material 3
├── domain/
│   ├── model/          # Чаты, сообщения, настройки, проверка адреса
│   ├── repository/     # Контракты хранения и API Ollama
│   └── usecase/        # Управление чатами, подготовка реплик, обновление настроек
└── data/
    ├── network/        # HttpURLConnection, NDJSON, отмена запроса
    └── storage/        # SharedPreferences и JSON-кодек истории
```

- **`presentation`** отображает `ChatUiState`, отправляет `ChatAction` и обрабатывает одноразовые `ChatEvent`. `ChatViewModel` публикует состояние через `StateFlow`, события — через `SharedFlow`. `MainActivity` подключает экран к жизненному циклу и обрабатывает буфер обмена Android.
- **`domain`** содержит модели, контракты репозиториев и сценарии работы. Слой не зависит от Android, Compose, ресурсов и конкретного хранилища.
- **`data`** реализует контракты сети и хранения. HTTP-запросы и кодирование истории выполняются на IO. Очередь сохранения объединяет промежуточные снимки и работает в scope приложения.
- **`di`** связывает реализации с контрактами. Hilt не используется.

Экран не выполняет сетевые запросы и не записывает настройки при отрисовке. ViewModel сохраняет текущий запрос при пересоздании Activity. Отмена корутины закрывает HTTP-соединение; идентификатор запроса исключает устаревшие фрагменты ответа.

Прикладной интерфейс полностью написан на Compose, без XML-экранов и `AndroidView`.

## API и хранение

Ollink обращается напрямую к HTTP API Ollama; отдельный сервер-посредник не требуется.

| Запрос | Назначение |
|---|---|
| `GET /api/tags` | Список установленных моделей |
| `POST /api/chat` | История с ролями `user` и `assistant`, выбранная модель и `stream: true` |

Ответ читается как NDJSON и отображается по мере получения. Поле `thinking` не выводится в интерфейс. Документация: [chat](https://docs.ollama.com/api/chat), [tags](https://docs.ollama.com/api/tags), [streaming](https://docs.ollama.com/api/streaming).

Таймаут подключения — **10 секунд**, чтения списка моделей — **15 секунд**, чтения ответа модели — **5 минут**. Последний параметр ограничивает ожидание данных, а не общую длительность генерации.

Настройки хранятся в SharedPreferences `connection`, диалоги — в `history` в JSON. Сохраняются сообщения, названия, выбранный чат, привязка к серверу и модели, а также черновики. Формат совместим с предыдущей версией Ollink. Синхронизации истории между устройствами нет.

Текущая версия предназначена для текстового чата. При подключении по HTTP сообщения передаются без шифрования, авторизация в приложении не реализована. Используйте такой сервер в доверенной локальной сети и не пробрасывайте его порт в интернет.

## Проверки

Сборка, JVM-тесты и статический анализ:

```bash
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

JVM-тесты проверяют адреса сервера, контекст повторной генерации, use cases, совместимость JSON-формата, выбор чата после удаления, отмену ответа и ViewModel с подставными репозиториями. Тестовый HTTP-сервер проверяет потоковый протокол: Unicode, последний фрагмент, ошибки HTTP/NDJSON и незавершённый ответ.

Compose UI-тесты на эмуляторе или тестовом устройстве:

```bash
./gradlew :app:connectedDebugAndroidTest
```

`ChatFlowTest` проверяет отправку, пересоздание Activity, черновики, поиск, восстановление истории, переименование/удаление, остановку и повторную генерацию, в том числе с открытой клавиатурой. Тесты используют локальный HTTP-сервер внутри устройства.

**`ChatFlowTest` очищает историю и настройки Ollink на тестовом устройстве.** Запускайте его на эмуляторе или устройстве без важных диалогов.

`ComposeResponsiveLayoutTest` проверяет размеры окна от 280 до 1000 dp, низкие окна, шрифт до 200%, длинные сообщения, тёмную тему и сетку 2×2. Размеры моделируются через `DeviceConfigurationOverride`.

Отчёты:

- JVM-тесты: `app/build/reports/tests/testDebugUnitTest/`.
- Lint: `app/build/reports/lint-results-debug.html`.
- Запуск UI-тестов через Gradle: `app/build/reports/androidTests/connected/`.

Для проверки с реальной моделью выполните шаги подключения, отправьте несколько связанных сообщений, остановите генерацию и повторите ответ. Проверьте также поворот экрана и открытие/закрытие клавиатуры.

## Если подключение не работает

| Симптом | Что проверить |
|---|---|
| Соединение сразу отклоняется | Ollama запущена и слушает сетевой интерфейс, а не только `127.0.0.1`; указан правильный порт |
| Подключение завершается таймаутом | IP компьютера, firewall, общую сеть и изоляцию клиентов на роутере |
| В списке нет моделей | Выполните `ollama list` на компьютере и при необходимости загрузите модель |
| Старая модель чата недоступна | Верните её на сервер или выберите другую модель для нового диалога |
| Первый ответ долго не появляется | Модель может загружаться в память или выполнять вычисления до выдачи текста; проверьте журналы Ollama |
| Адрес работал раньше, а теперь нет | IP компьютера мог измениться; обновите адрес в настройках подключения |

На Linux проверьте, где сервер слушает порт:

```bash
ss -ltn 'sport = :11434'
```

Для обычного доступа по IPv4 из локальной сети ожидается `0.0.0.0:11434` или адрес сетевого интерфейса компьютера. `127.0.0.1:11434` доступен только самому компьютеру.

Проверка API на компьютере:

```bash
curl http://127.0.0.1:11434/api/tags
```

Если этот запрос работает, а тот же API с телефона недоступен, проверьте адрес прослушивания и сетевой доступ. После этого повторите проверку в браузере телефона по локальному IP компьютера.
